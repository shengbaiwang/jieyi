# 翻译 Token 效率

本次优化覆盖普通/并发执行器的 EPUB 单 atom 包装与提示词，以及并发执行器的初始
输出预算、截断验收、请求审计和准确预览。不改写模型配置，不自动重译已完成内容。

## 请求准备与结构恢复

`workflow.requests.prepare_translation` 返回提示请求、保护映射、当前术语和结构标志。
Web 并发执行器与 `prompt-preview?optimized=true` 共用这一路径。普通 CLI/同步 API
保留自己的 TM 上下文，默认预览与其一致；两条执行路径都使用同一个保护 codec。

- 唯一 SourceAtom 完整包住正文：程序保存精确的外层开闭标签，只发送内部受保护正文。
- 两个及以上 SourceAtom：继续发送完整边界，防止不同 DOM 片段串译或遗漏。
- 内联标签、脚注、URL、引文、源文中的字面占位符：保护和顺序校验不变。
- 无占位符的正文：省去无关 DOM 结构说明。存在内联占位符时保留对应的格式规则。
- 恢复外层包装后，仍通过原有结构解析、空内容检查、术语 QA 和人工确认流程。

没有为了缩短提示而裁掉任何新的原文、术语、风格或邻段内容。原有 max_context_chars
截断规则保持不变。也没有启用跨段合并生成或降低用户的推理档位。

## 输出预算与异常响应

并发草译初始上限：

```
min(任务硬上限, max(512, 2 × 受保护原文字符数) + 推理预留)
```

推理预留为 economy=0、balanced=2048、performance=4096。它仅提高过小的初始上限，
不要求模型生成到上限，也不改变 reasoning effort。局部结构修复仍使用 economy。
低上限已足以完成的请求未必因此减少用量；主要收益是避免先花掉整轮推理额度、
再重复发送完整提示。最终消耗必须用实际 usage 衡量。

Chat Completions 的 length、Responses 的 incomplete/max_output_tokens、Anthropic
的 max_tokens、Gemini 的 MAX_TOKENS 都按不完整结果处理。即使有可见文本，也不能
直接保存半截译文；在硬上限内有限重试，耗尽后隔离。空网关响应仍最多原额度重试一次。

## 指标

并发执行器在每次模型返回后写入 `audit_events`，action=`model_call`、entity_type=`job`。
内容包括段落 ID、阶段、计算档位、请求字符数、输出上限、输入/输出/推理/缓存用量、
输出字符数、停止原因和耗时；不包含原文、密钥或完整响应。

- `model_call_count`：已记录的返回次数；不包含适配器内部 HTTP 重试或未返回请求。
- `retry_call_count`：同一次草译/修复调用因空响应或不完整输出而追加的返回次数。
- `repair_call_count`：结构修复阶段的所有已记录返回次数，可能与上一项重叠。
- token 合计仍由原有批次/旧候选汇总，审计仅用于拆解，不再次累加；推理已包含在输出内。

旧任务可能只有部分阶段存在逐次审计，历史调用不补算。暂停或进程中断时，已返回请求的
审计可能先于批次完成落盘，因此审计与批次合计不一定瞬时一致；未返回的服务端用量
仍需向供应商核对。

## 可重复的离线比较

```
.venv/bin/python scripts/benchmark_translation_prompts.py \
  --database jieyi.db \
  --baseline a0e936fc302f4461eedf0f478563fbdb69ef202c \
  --jobs 3
```

脚本以只读连接打开数据库，不初始化模型供应商；从指定的可信本地 git 版本加载旧
提示词构建器，在相同上下文下比较包装与结构说明优化前后的请求字符数，并逐段断言
保护文本可以完整恢复原始源文。比较覆盖所选任务范围，包括已翻译段落，仅输出汇总。
该脚本用于本次包装/提示词优化的比较，不是任意历史执行器的完整性能模拟器。

本次对本地最近三本 EPUB 的离线检查中，请求字符量下降 8.31%～11.22%。该数值不代表
模型 token、推理消耗或账单降幅。没有为验证而自动发起新的付费翻译；真实译文质量和
成本需结合后续同模型、同档位的实际请求以及人工对照评估。

回归覆盖单/多 atom、内联格式和字面标记、预览与实际请求一致、邻段和术语保留、
短段推理空转避免、截断结果重试与隔离、用量不重复累加，以及原有跨段隔离、恢复和 QA。
