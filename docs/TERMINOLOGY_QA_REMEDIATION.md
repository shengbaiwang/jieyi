# 术语误报研究与修复方案

日期：2026-09-02。状态：研究完成，尚未实施。

建议将术语约束从“原文包含某个词”改为“该词在这个具体位置使用了已批准的义项”，并把待机器判义与人工必检分开。翻译提示、质量检查和批准后的回查必须共用相同的适用性结论。

## 为什么简单修补不够

用现有检查函数对真实译文做内存对照，结果如下；没有写回数据库。

| 方案 | 术语告警段落数 | 结果 |
|---|---:|---|
| 当前规则 | 94 | 缺少“国家”即报错 |
| 仅把这些 error 改成 warning | 94 | 按现有人工队列逻辑，仍全部属于必检 |
| 缺少义项证据就走现有 ambiguous 分支 | 247 | 每个命中段落都告警，已有“国家”的译文也会告警 |

第三项通过给同一术语配置一个不可能命中的临时语境关键词来复现现有 unresolved 路径，只在内存中运行。

另外验证了两类缺陷：

- 给 state 加 governments 关键词，输入“Governments discuss the state of nature.”，现有算法仍错误要求“国家”。整段政治词汇不能证明某次 state 使用政治实体义。
- 构造一个同时含两次 state 的句子，并故意交换“国家”和“状态”的对应位置，只要译文有“国家”，当前检查就不报错。因此目前也存在漏报。

当前 render_terminology_constraints 会把“自然状态”的示例生成 state → 国家 [MANDATORY]。质量检查与后续翻译都会受影响。

## 推荐设计

### 1. 明确“批准义项”和“每次适用”的区别

批准表示：在这个义项确实适用时使用该译法。它不表示整个词形在全书只有这个义项。

建议显式区分全局固定译法与按语境生效的译法。有 sense、disambiguation 或语境条件的现有条目，默认按语境生效；不能因为关键词为空就退回全局强制。简单专名等固定译法继续支持严格一致性检查，但不靠“看起来像专名”自动授予全局强制范围。

sense 和 disambiguation 是自然语言说明，不能假装正则程序已经理解它们。待判义时把说明交给模型，并允许输出“该义项不适用”，即使词库只有一个已批准义项。

### 2. 按出现位置判义，再检查译法

每个匹配保存原文起止位置和所在句子。首先处理已批准长词组对短词的覆盖；没有词组规则的复合词进入语境判断，不凭连字符一律排除。

建议分两步保存结论：

1. 原文适用性：适用 / 不适用 / 待判断。
2. 适用时的译法核验：一致 / 疑似不一致 / 无法判断。

局部语境优先使用所在句，指代不清时补充邻句或段落。关键词只作为证据，不能单独决定整段中所有同形词的义项。多个相同词、不同义项可以在同段并存。

语境模型输出必须绑定已提供的出现位置、术语 ID 和原文证据；核验译法时还要指出实际译文片段。程序复验引文与字符位置。词库之外的常用义应能返回“不适用”，不能被迫从已有译法里选一个。

不得用模型自报置信度直接等同于“确定错误”。模型核验的问题应标明来源；高风险强制判断需要真实样本验证。未能确认的项保留待处理状态。

### 3. 机器核验状态与人工问题分开

建议在数据与页面中区分：

| 状态 | 处理方式 |
|---|---|
| 待 AI 判义、尚未核验 | 自动任务待办，可见进度，不直接计入人工必检 |
| 已判定不适用或译法一致 | 不产生术语问题 |
| 适用且检测到不一致 | 展示原文义项、当前译法、要求译法及证据 |
| AI 核验后仍需用户选择义项或译法 | 人工复核 |
| 模型不可用、超时或失败 | 显示未完成与重试状态，不宣称通过 |

人工队列应使用明确的“需人工处理”属性，而不是将所有 warning 都视为必检。脚注结构错误、翻译失败和模型明确提出的人类判断事项仍保留。

术语批准回查页可把同一术语的待核验项合并为一组，并显示段落范围；人工问题仍保留逐段定位。页面分别显示“待机器核验”“发现不一致”“待人工决定”“分布抽检”，避免计数下降被理解成全部通过。

现有约 8% 抽样只针对已 AI 审校的干净段落；待术语判义的段落不能通过隐藏告警变成“已核验干净”。是否继续保留该比例是独立产品决定，本次无需调整。

### 4. 翻译与审校共用结果

已确定适用的义项才生成对具体出现位置有效的强制译法。待判义条目保留条件说明，例如“仅当 state 指政治实体时译为国家；状态、行政州和动词义不适用”，并要求上下文判断。

独立审校不能收到由旧规则误判的“必须修正问题”，否则可能把合理译文改坏。普通翻译路径、优化/批处理路径、批准回查与人工编辑后的 QA 都必须使用同一套逻辑。

### 5. 局部异步回查与缓存

批准术语后立即保存批准决定，再安排受影响文本的核验任务，不让批准接口同步等待大量模型请求。当前这本书首轮应检查全部 247 个命中段落的相关出现位置，而不只检查 94 个已报警段落，以防已有“国家”掩盖错位或漏译。

复用当前模型适配器、并发限流及费用统计能力；按上下文长度分批、限制预算、保留失败重试。模型未配置时可完成本地筛查并明确报告待核验量。

现有 term_candidate_evidence 只保存分散抽样，适合术语发现；它不是每次出现都已判义的证据。可复用精确偏移校验方法，但需另存全量出现位置和核验记录。

原文判义缓存绑定原文/语境哈希、术语义项版本、规则与模型版本。译法核验另绑定当前译文哈希；人工改译后使核验过期。只改变译文时，可以保留仍有效的原文判义结果。

## 实施顺序与代码边界

第一阶段应一起交付：停止缺少语境证据时的全局强制；统一条件式提示；增加待机器核验状态；修正人工队列计数与完成语义。这是止住错误约束传播的最小完整改动，不能只改一个 severity。

第二阶段补齐按出现位置的判义与译法核验、后台任务、缓存和来源证据展示，随后核验这本书的受影响段落。

## 验收标准

- 上述自然状态、州名、动词、城邦案例不再被强制译为“国家”。
- 真正政治实体义误译为“状态”的正例仍可检出，不能靠隐藏所有术语问题降低计数。
- 同段不同义项、正确词出现在错误位置、state of affairs / affairs of state、多个竞争义项都有用例。
- 参考文献保留原文的处理依据明确项目策略；普通正文整段未翻译不能借此豁免。
- 未核验、服务失败与已通过的统计可区分；未知项不能使页面显示全部完成。
- 修复前后原文、机器译文、人工译文和人工确认记录保持一致；非术语问题不丢失。
- 原文或译文变化能失效相应缓存；重复重算不生成重复人工问题。
- 建立人工标注的小型真实语料，同时报告误报和漏报；不能用“最后还剩几条”单独衡量质量。

## 研究依据与适用范围

Baek 等的 ACL 2023 研究把同形异义约束的语境适用性列为受约束翻译的重要问题，并引入消歧模块。这支持“先判断是否适用，再施加约束”的方向，但其具体模型效果不直接代表本项目表现：[Towards Accurate Translation via Semantically Appropriate Application of Lexical Constraints](https://arxiv.org/abs/2306.12089)。

Bejgu 等的 ACL 2024 研究指出，真实文本中的词义处理既需要定位文本跨度，也需要将其关联到义项；不能假定所有跨度和候选义项都已完整提供。这支持按实际出现位置保存判断，并保留词库外义项出口：[Word Sense Linking: Disambiguating Outside the Sandbox](https://aclanthology.org/2024.findings-acl.851/)。

上述实施步骤是结合本项目代码与实际数据提出的工程方案，尚未做模型质量、费用或耗时基准测试。
