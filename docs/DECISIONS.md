# 工程决策记录

## ADR-001：建立独立核心，不 fork 后拼接

状态：已采用。

TBL 是 AGPL-3.0，Supervertaler Workbench 是 MIT，而且二者分别围绕 Web/CLI 长文流水线和 PyQt CAT 工作台演进。直接拼接会同时耦合许可证、UI、持久化和模型调用。介译只借鉴公开功能思想，核心从零实现；未来通过适配器和标准交换格式集成。

## ADR-002：先做模块化单体

状态：已采用。

首版使用单一 Python 包和 SQLite，模块之间仍保持端口边界。这样部署、调试和事务处理简单；当多人协作或吞吐量需要 PostgreSQL/worker 时，可以替换外层实现，不必把领域逻辑拆散成微服务。

## ADR-003：核心零第三方依赖，API 可选

状态：已采用。

领域、工作流、SQLite、CLI 和 OpenAI-compatible HTTP 调用都使用标准库。FastAPI/uvicorn 是可选依赖。这减少了本地批处理和私有部署的安装面，同时保留正式 Web 产品的接口。

## ADR-004：机器候选与人工确认分离

状态：已采用。

模型候选不可直接成为“已确认译文”。人工决定包含译文、操作者、理由和时间，模型重跑不会覆盖它。这是审校、回滚、训练数据治理和责任追踪的基础。

## ADR-005：先做确定性 QA，再做模型审校

状态：已采用。

只有脚注标记和强制术语等高置信不变量进入确定性检查。数字和括号在本地化、排版及结构恢复后容易产生误报，交由模型审校与人工判断；LLM 审校输出仍是候选。

## ADR-006：保护结构后翻译，严格验证后恢复

状态：已采用。

受 TBL 的标签保护原则启发，介译独立实现了适用于纯文本学术材料的占位符协议。协议不依赖模型“自觉”保留引文和技术内容，而是验证数量、唯一性和顺序。结构修复是独立候选阶段，失败时不推进检查点。

## ADR-007：只有人工确认进入 TM

状态：已采用。

受 Supervertaler 的项目 TM、精确优先和模糊译例工作流启发，介译将确认译文自动沉淀为项目 TM。机器草稿和模型审校不会污染 TM；模糊匹配只进入提示上下文，不自动确认。

## ADR-008：提示词预览与真实请求使用同一构建器

状态：已采用。

提示词是翻译工程的可审计输入。API/CLI 预览直接调用供应商请求所用的 `build_messages()`，不得维护第二套近似模板。

## ADR-009：EPUB 先规范化导入，后实现格式回写

状态：已采用。

EPUB 是包含 OPF、spine、XHTML 与资源文件的容器，而不是普通 HTML。第一阶段按标准阅读顺序安全提取文本并映射到统一段落模型，使翻译、TM、检查点和 QA 立即可用。无损回写需要额外保存 DOM 定位、内联标签、导航和资源映射，在建立对应数据模型前不以“支持 EPUB”掩盖格式丢失风险。

## ADR-009A：原书归档与模板式结构化译文阅读

状态：已采用，推进 ADR-009 的第二阶段。

导入必须同时保留原始 EPUB 字节和逐成员索引；规范 Segment 继续作为翻译、术语、审校、
QA、TM 与人工确认的主对象。SourceAtom 与 TextNode 地址作为可回放映射层，模型输入用
受保护的内联标签和 atom 边界，输出必须逐 atom 校验后保存。阅读器从原 XHTML 生成
原版、仅译文和双语视图，所有书内内容均视为不可信网页：禁止脚本、外部网络、事件
属性、表单和危险 URL，只开放经清洗的同书 CSS、图片、SVG 与字体。相同 SHA-256 的
原文件可为旧文档补全资源，但不得替换已有译文或人工决定。

## ADR-010：质量问题绑定当前译文与检测器版本

状态：已采用。

质量规则会随语种、规范化策略和回归样本演进，旧任务产生的问题不能永久代表当前
译文。每次译文或术语变化都生成新的质量快照；旧问题只标记为已解决而不删除。
查询同时校验译文哈希，检测器升级则触发一次性全库重扫。高置信度结构错误与允许
本地化的风险提示分级展示，避免低精度规则阻断人工流程。
