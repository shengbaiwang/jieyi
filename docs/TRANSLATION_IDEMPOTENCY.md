# 目录与翻译防重审计（2026-09-07）

## 已实现

- 目录身份与位置分离：PDF/EPUB 使用原始导航条目的独立 ID，普通标题使用段落 ID。名称、页码、段落序号、共享范围均不作为选中身份。同一页的不同书签可以独立选择；原书没有坐标时不虚构精确位置。
- 单页连续点击：同步提交门在首次 await 之前上锁，成功或失败都释放，旧释放函数不能解锁下一次提交。
- 多标签页同时提交：后端先合并重复、交叉和相邻选区，在 SQLite 写事务中查找并复用相同配置的未完成任务。
- 多任务、多进程重复执行：按真实数据库路径和文档 ID 获取操作系统文件锁，普通、优化、后台执行入口共用。锁忙返回 HTTP 409；不同书互不影响。启动恢复不会把另一个活进程的任务误标为已中断。
- 已有结果：所有执行入口跳过机器译文、编辑稿、复核稿、人工确认稿。队列拿到模型槽位后再检查源文和已有译文。
- 结果保存：每段完成即可保存，不再等待整批其他段落。质量问题、正文和 EPUB 结构处于同一事务（优化入口的可用候选也一并提交），保存前再次核对原文及人工修改，旧结果不能覆盖较新的内容。
- 原文变化：未能提交的旧结果不会错误推进完成状态；保留当前断点，等待使用新原文续跑。
- 后台任务的普通暂停：停止派发新的草译、空响应重试及结构修复请求；已发请求保存期间不能重启同一本书。启动后立即暂停也不会重新派发。
- 相同文字出现在不同段落时仍分别处理，防重依据是位置身份，不是文本内容。

## 取消与失败收尾

用户已明确批准并应用取消处理修复。强制取消底层异步任务，或某一并发组致命失败时，保留文档执行锁，停止后续派发，等待已发请求完成或按现有 provider 超时退出并保存，再释放执行锁。反复取消不会提前解锁，启动前收到暂停/取消也不会派发请求。已取消任务不会因关闭服务、迟到的超时或原文变化而恢复成可续跑状态。

已有请求可能继续由服务商计费；停止状态会立即显示，但完全结束需要等待。该处理不提高超时、不主动新增请求。保存完成后，暂停任务可继续；已取消任务保持取消，新任务跳过已保存译文。

强制取消回归测试已移除 xfail，普通与优化入口均纳入测试。审批时的补丁已合入实际代码，保留为 `CANCELLATION_FIX_APPROVED.patch` 历史快照，后续以工作流代码及测试为准，不要重复应用。
