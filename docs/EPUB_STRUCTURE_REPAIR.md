# EPUB 文本片段修复协议

## 问题

一个标题或段落可映射至多个 SourceAtom。中文语序可能让模型把句尾放在最后一个闭合标记后；此时模型已经生成中文，但无法写回 EPUB。旧的修复提示只允许改标记、不允许调整措辞，导致相同失败重复三次。

## 实现

- 草译和审校请求明确标注 SourceAtom 的开闭边界。
- 结构化 EPUB 修复使用 JSON：每个开标记是一个键，每个值只包含对应源片段的译文。
- 模型可为对齐原文片段而做最小幅度的语序调整，必须保留信息和术语；书名片段保持书名。
- 程序按原文顺序装配所有边界，检查键集合、重复键、空片段和各片段内部标记的数量与顺序。模型返回的普通字符按 XML 文本转义。
- 严格 XML 校验继续拒绝越界文本、未知外层元素、嵌套片段及身份或顺序错误。不存在删除句尾后强制接受的路径。
- 普通执行器和并发执行器共用协议；普通 TXT/Markdown 的标记修复方式保持兼容。
- 验收失败继续隔离，提供具体中文原因。失败候选的零指标是诊断快照；单段任务在检查器中使用包含重试的任务总用量，进度采用实际范围。

## 回归覆盖

`tests/test_protection.py` 覆盖 JSON 装配、XML 转义、斜体标记和异常响应拒收。
`tests/test_epub_roundtrip.py` 使用块级换行和斜体书名复现真实结构，两种执行器均验证完整译文、相邻段落隔离、用量计数、EPUB 导出及资源保留。连续无效修复不得留下部分译文。

本地验证无需网络。真实模型验证通过工作台的「草译本段」触发；不需要重新导入书籍或重译全书。
